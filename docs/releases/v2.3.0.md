# AI Software Toolkit v2.3.0

**Draft for maintainer review — not published.**

Simplify adoption without reducing assurance coverage. All 33 checks remain
visible; all checks remain optional, and Core keeps its 12 advisory checks.

## What's changed

- Shorter README, complete [activation index](../activation.md), and retained
  operational guidance and historical verification links.
- Fresh `init` defaults to `--install-set starter`: Proof, the seven existing
  starter skills, and 11 Core workflows. Use `--install-set full` explicitly
  for the full workflow set. GitHub profile and Pages remain separate choices.
- Starter excludes Trivy and lifecycle workflows until explicitly adopted.
  Missing scanner prerequisites stay unverified. Lifecycle and polyglot stay manual.
- Proof-only and Claude-only fresh installs create no unrequested client directories.
- Existing installations retain full behavior when installation-set metadata is
  absent. Configuration and lock persist new choices; no migration or pruning occurs.
- Existing doctor commands expose per-check selection, files, gaps, evidence
  revision/status, guide, and next steps. JSON fields are additive; diagnostics
  never execute producers, access credential values, or change enforcement.
- [Documentation mappings](../proof/documentation-validation.md) scan tracked
  repository files. Non-Git source snapshots use deterministic exclusions for
  generated output and dependencies. Missing policy or comparison base still fails.
- Specification-driven development is tool-independent. Spec Kit is an optional
  integration with its existing identifier and independent version 1.0.0.

## Distribution and compatibility

The CLI reports 2.3.0. Runtime/schema paths, Core/GitHub policies, evidence
contracts, documentation-policy format, and preset/schema versions are preserved.
Existing selections, customized files, owned workflows, and update behavior remain
compatible. Review the [installation guide](../install.md) before adopting changes.

The default CLI archive excludes `tooling/speckit/` and the manual preset packager.
Standard release assets omit the preset ZIP and its checksum. The full source
archive still contains the preset and packager for [explicit adoption](../../tooling/speckit/engineering-standards/README.md).
Historical releases and their assets, including v2.2.1, remain unchanged.

## Candidate evidence and assets

Review the CLI archive, full source archive, individual checksums, release notes,
Action metadata, distribution-verification record, manifest, and SHA256SUMS together.
The manifest identifies exact source, required hosted CI, consumer verification,
archive inventories, sizes, and hashes. Hosted acceptance verifies fresh consumers
and a consumer installed from published v2.2.1 against the candidate CLI archive.
No extra local tests are run. Packaging/hash inspection does not establish native
build provenance or certify an application. No consumer deployment, credentials,
branch protection, automatic activation, new repository, or add-on release is included.

The Action name remains **AI Software Toolkit Proof Attestation**, with the same
repository path, required inputs, and execution. Marketplace listing status is
separate from this draft; no new listing or publication is performed here.

## Recovery

Keep the published v2.2.1 assets and your repository configuration. Preview updates,
review conflicts, and use the recorded rollback when needed. There is no application
database migration. Publishing requires a separate explicit maintainer decision.
