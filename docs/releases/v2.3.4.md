# AI Software Toolkit v2.3.4

**Draft candidate; not published.** Stable installation examples continue to
use v2.3.3. This draft packages the reporting improvements reviewed in
[#164](https://github.com/ravisingh11/ai-software-toolkit/pull/164).

v2.3.3 added historical PR/main examples and an authentic README screenshot.
v2.3.4 adds actionable records for actual runs: why they ran, what they checked,
what remains uncertain, and what should happen next.

## Reporting improvements

- Maintainer Distribution Acceptance captures the actual checkout, event
  revision, invocation, run/attempt, and PR head/base when supplied. A final job
  summary and retained JSON/Markdown report describe its named steps. A main
  push records its own revision without inventing PR metadata or relabeling a
  previous PR result.
- The CLI's human-readable `check` report groups supplied evaluator results as
  passed, failed, blocked, unverified/not run, stale evidence, and inactive.
  It retains original evaluator decisions, statuses, scores and evidence links;
  machine-readable JSON and exit decisions retain their existing contracts.
- Gaps identify the authoritative provider, recorded reason, activation guide
  and next step. A relevant project skill is suggested only when its files are
  installed. Suggestions and installation do not establish agent execution.
- Raw workflow outcomes and conclusions remain separate, including failures
  masked by `continue-on-error`, missing/skipped work, and cancellation after
  successful steps. Only reporting/upload are best effort; they do not repair
  producer failures. Reporting-time job status is distinct from the final
  GitHub run conclusion.
- Focused hosted regressions cover real evaluator cards, supplemental-only
  success, stale/wrong subjects, missing authority, inactive checks, failure
  retention, cancellation, safe receipt rendering, and input preservation.

## Compatibility and limits

The candidate CLI reports 2.3.4. Its human-readable report format intentionally
changes; automation should use the existing JSON output. Evaluator, catalog,
provider, profile, policy and schema contracts remain unchanged from v2.3.3.
All 33 checks stay discoverable; only selected, applicable checks contribute to
evaluation. All checks remain optional, Core advisory, lifecycle/polyglot manual.

Acceptance reports describe only their own steps. They do not prove that every
selected toolkit check ran, assess all merge requirements, authenticate a
supplied evaluator card, or establish deployment health. The presentation JSON
is not a new Proof evidence document. Abrupt cancellation, runner loss or checkout
failure can prevent reports/artifacts; absence is not a pass. GitHub artifact
access and retention apply.

No new producer trigger, automatic repair, credential, provider selection,
enforcement, branch-protection, migration or deployment change is included.
The reference app remains independently pinned/deployed to its recorded toolkit
revision; preparing this draft does not upgrade it or refresh its live evidence.
Historical release, deployment, real skill and hook evidence remain intact.

The Action name, inputs and execution are unchanged. Marketplace metadata is
included without claiming listing acceptance. Spec Kit remains excluded from
the CLI and standard release assets; its independent 1.0.0 preset and manual
packager remain in the full source archive.

## Draft verification and publication boundary

Review the exact-source CLI/source archives, release notes, individual checksums,
SHA256SUMS, manifest, hosted distribution verification and Action metadata
together. The attached CLI must be the exact bytes exercised by hosted CI,
not a replacement local rebuild. Downloaded draft assets are compared with
their recorded hashes, sizes, inventories and source references.

The draft manifest distinguishes the tested preparation commit from main.
The preparation PR remains open for review. Before publication, merge the
reviewed preparation, run final merged-source Distribution Acceptance, and
refresh/reverify the draft against that exact source. Publication requires a
separate maintainer decision; this draft grants none.

Hashes and download comparisons establish asset integrity, not native build
provenance or application certification. Hosted fixture acceptance does not
prove every optional provider ran. No extra local suites, producers or new
agent execution are claimed. Retain v2.3.3 and consumer ownership/configuration
records for a reviewed rollback; no automatic consumer migration is included.
