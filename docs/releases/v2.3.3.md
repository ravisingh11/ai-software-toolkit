# AI Software Toolkit v2.3.3

This patch makes the scorecard's SDLC examples easier to understand: PR review
and verification after merge have separate checks, evidence subjects and next
decisions. The README shows an authentic screenshot from the reference app and
links to its report.

## Changes

- Scorecard pages show two recorded examples before the detailed PR evaluation:
  advisory PR policy evidence, and workflow observations for a main revision.
  Each example retains its own invocation, source run, revision, outcomes and
  next decision. The examples come from different changes and are explicitly
  historical; they do not claim to be the latest evaluation or deployment health.
- The reference app has its own examples. Other consumers see clearly labeled
  toolkit teaching examples rather than inheriting another repository's scores.
- [Reading SDLC evidence](../proof/reading-evidence.md#separate-sdlc-checkpoint-examples)
  explains the distinction. The README includes the original reference-app
  screenshot, including its failed size check and unverified coverage.
- The CLI reports 2.3.3. README and quickstart installation examples use v2.3.3.

The example-page change was reviewed in
[#165](https://github.com/ravisingh11/ai-software-toolkit/pull/165); the screenshot
was reviewed in [#166](https://github.com/ravisingh11/ai-software-toolkit/pull/166).
The separate actionable workflow-reporting work in PR #164 is not included.

## Compatibility and adoption

All 33 checks remain discoverable. All checks remain optional to adopt, Core
stays advisory, and lifecycle/polyglot execution remains manual. Evaluator,
catalog, provider, profile and schema contracts are unchanged from v2.3.2.
The page examples change presentation without changing evaluation results,
scores, selection, enforcement, producer credentials or workflow triggers.

Existing consumers retain their configuration, custom files and update choices.
Adopt this patch through a reviewed pinned update. Publishing the toolkit does
not update or deploy an application automatically. The reference app's README
screenshot is merged separately; its existing deployment and skill evidence
remain historical records with their original identities.

The Action remains **AI Software Toolkit Proof Attestation**, with unchanged
inputs and execution. Attached Marketplace metadata does not establish listing
acceptance. Spec Kit remains excluded from the CLI archive and standard assets;
its independent 1.0.0 preset and manual packager remain in the full source archive.
Historical releases and their assets are preserved.

## Verification and recovery

The release manifest records the exact source commit and tree, required
preparation CI, and merged-source Distribution Acceptance. The attached CLI must
be the exact bytes exercised by hosted acceptance, not a replacement local build.
Hosted checks include renderer regressions and the existing fresh/legacy
consumer and evaluator compatibility cases.

Review the source and CLI archives, release notes, individual checksums,
SHA256SUMS, manifest, distribution verification and Action metadata together.
Downloaded assets are compared with the verified draft before publication.
Checksums establish asset integrity, not native build provenance. Fixture
acceptance does not establish that all optional providers ran or that an
application is healthy. No extra local tests or new agent execution are claimed.

Retain v2.3.2 and the consumer's prior configuration and ownership records for a
reviewed rollback. This toolkit release includes no application database
migration, deployment or branch-protection change.
