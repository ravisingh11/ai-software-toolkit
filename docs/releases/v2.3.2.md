# AI Software Toolkit v2.3.2

This patch makes SDLC checkpoints and their invocation explicit, improves the
README diagrams, and updates the optional CodeQL Action template. Existing
control selection, evaluation and scoring contracts remain unchanged.

## Changes

- [SDLC checkpoints](../sdlc-checkpoints.md) explain coding finished, pre-commit,
  commit creation, post-commit feedback, pre-push, PR updates, pre-merge and
  post-merge. All 33 checks remain mapped to a checkpoint or later handoff.
- README diagrams connect equal-sized process boxes to invocation points and
  toolkit capabilities, with stronger colors and more space for vertical arrows.
  Examples cover skills, read-only diagnostics, CI inspection and unit-test wiring.
- Maintainer Distribution Acceptance reports the invoking event/action, Git ref,
  checkpoint, actual tested checkout, separate event revision, PR head/base when
  supplied, and run/attempt. PR updates contrast with pushes to main. Its new
  main-branch trigger is maintainer-only and is not a consumer workflow default.
- Optional CodeQL init/autobuild/analyze pins advance together from v4.39.0 to v4.39.1
  (`9b3254085494b55a0f7c4c2b3d2d52cc712ce370`) in shipped, installed and embedded
  demo and combined security workflows. No permission or provider-selection changes are included.
- Correct the release index/changelog to identify v2.3.1 as published while
  preserving its preparation notes and immutable historical assets.

## Compatibility and invocation boundaries

The CLI reports 2.3.2. All checks remain optional to adopt; Core is advisory.
Lifecycle and polyglot execution remain manual. The evaluator, catalog, provider
contracts, profiles and schema versions are unchanged from v2.3.1.

Checkpoint names are guidance, not new operations, subjects or flags. Exact
staged-snapshot evaluation and a built-in commit-message producer remain future
capabilities. Working-tree feedback does not establish that partially staged
contents passed. Invocation labels are display context, not signed provenance
or a passing result. PR-head, integration-checkout and resulting-main evidence
retain their original subjects and are not relabeled across squash/merge.

Existing consumers retain selected checks, commands, credentials, custom files
and enforcement choices. A workflow pin update does not activate CodeQL or
supply missing evidence. No producer credential, branch-protection, deployment
or automatic migration change is included.

The Action remains **AI Software Toolkit Proof Attestation**, with unchanged
inputs and execution. Marketplace metadata is attached; it does not establish
Marketplace listing acceptance. The CLI excludes Spec Kit; the full source
archive retains the optional preset and manual packager, independently versioned
1.0.0. No historical release is replaced.

## Release evidence and recovery

Review the CLI/source archives, checksums, manifest, exact-revision hosted
consumer/evaluation verification and Action metadata together. The attached CLI
must be the exact bytes exercised by merged-source Distribution Acceptance.
Required CI verifies the preparation PR; the manifest separately records the
merged source and whether its tree matches the tested head.

Checksums and downloaded-byte comparisons establish asset integrity, not native
build provenance. Hosted fixture tests do not certify a consumer application or
prove that every optional provider ran. Historical Codex demonstrations and
reference app deployment evidence remain separate and unchanged; no new Claude
execution is claimed. No extra local tests were run.

Use a reviewed pinned update to adopt this release, preserve consumer configuration,
and retain the prior release assets for rollback. No application database
migration or consumer deployment is part of this toolkit release.
