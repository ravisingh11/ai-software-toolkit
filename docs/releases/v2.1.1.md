# AI Software Toolkit v2.1.1

**Status: release preparation for maintainer review. Not tagged or published.**

AI is the accelerant. Assurance is mandatory. This patch makes assurance
clearer in the README and published scorecard and makes standalone skill
replacement safer when `rsync` is unavailable.

## Changes since v2.1.0

- Stage the complete replacement skill before moving the installed copy.
  Restore the original after a failed promotion or handled interruption;
  preserve it and report its recovery path when rollback cannot complete.
  Failure-recovery coverage includes partial copies, rename failures,
  unsuccessful rollback, and termination. Recovery is per skill; uncatchable
  termination may still require manual recovery.
- Use **selected checks** and separate failed, blocked, unverified, and inactive
  counts. Inactive checks stay outside selected totals; empty enforcement is
  explicit. Selection does not prove execution or a passing result.
- Explain standards, agent skills, optional checks, and revision-bound evidence
  on the published page, with setup, skill catalog, and reference-app links.
  Refresh onboarding, release navigation, and shipped-capability descriptions.
- Update pinned attestation and cosign-installer actions and synchronize their
  distributed copies. Require maintainer review for this repository, retaining
  the owner-authored PR exception and separate required CI gates.

## Compatibility and adoption

This is a patch update from v2.1.0. Public Proof runtime paths, evidence and
policy schemas, and evaluation decisions are unchanged. The CLI reports 2.1.1;
the installed runtime contract and Spec Kit preset keep their independent
versions. Preview consumer updates and review preserved local edits.

All toolkit checks remain optional to adopt and enforce. The reference app's
polyglot examples remain manual. Repository-specific review requirements do
not make toolkit checks mandatory for consumers.

## Candidate artifacts and publication handoff

After the preparation PR merges, build the CLI archive and checksum plus the
Spec Kit preset ZIP from that clean, exact merge commit. Retain a
`release-manifest.json` with the full source SHA, build timestamp, each asset's
SHA-256 hash, and required CI links. Inspect the archive's embedded revision
and CLI version against the manifest. Review the artifacts before publication.

No `v2.1.1` tag, GitHub Release, or uploaded release assets are authorized by
this preparation. The maintainer decides whether and when to publish. When
publishing, remove the preparation status and reconcile the release index and
changelog status through the normal PR process. Keep notes tied to observed
evidence; do not replace unknown results with claims of verification.

## Recovery

For an installed consumer, use the managed update's recorded backup and
rollback guidance in the [installation guide](../install.md), preserving local
configuration. Use a reviewed prior toolkit revision if a rollout must stop;
preview changes before applying them. The restored v2.1.0 release remains the
published baseline until the maintainer approves v2.1.1.
