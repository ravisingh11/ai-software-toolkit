# AI Software Toolkit v2.1.0

AI Software Toolkit v2.1.0 brings the shared CLI, Proof evidence runtime, reusable agent skills, and optional quality recipes together.

## Included

- `ai-toolkit` discovery, preview/install, setup diagnostics, provider selection, and managed updates with conflict preservation and rollback.
- Project skills for Claude Code and Codex, with independently adoptable Proof, skills, and QA components. The README and onboarding guide now cover `.claude/skills/`, `CLAUDE.md` guidance, shared client selection, optional QA bootstrap, and setup without installing Actions workflows.
- Defensive testing, test-integrity and changed-code coverage helpers, and language-specific lint/architecture recipes. Explore the [sample application](https://github.com/ravisingh11/ai-software-toolkit-reference-app) and its manual Java, TypeScript, Python, PHP, and Scala examples.
- CodeQL default-setup collection with native configuration, run, and analysis provenance checks; isolated credential-bearing provider adapters.
- Optional artifact, IaC, SBOM, vulnerability, attestation, DAST, runtime, and soak providers.
- Scorecards with provider configuration/run links, explicit missing evidence, duplicate PR-size provenance checks, and publication freshness/refresh.

All checks remain optional to adopt and enforce. Polyglot examples remain manual.

## Migration

This is a major-line upgrade from v1.0.0. Review [runtime migration](https://github.com/ravisingh11/ai-software-toolkit/blob/6407413d60f4b77f686e52d0a146941fa8e1705e/docs/proof/migrating-from-guardrails.md) and [provider credential isolation](https://github.com/ravisingh11/ai-software-toolkit/blob/6407413d60f4b77f686e52d0a146941fa8e1705e/docs/providers/README.md#migrating-from-the-pull_request-templates). Current runtime paths and variables use `.proof/` and `PROOF_*`. Credential-bearing adapters require the documented default-branch-restricted `proof-providers` environment. Preview updates and review preserved conflicts before applying them.
