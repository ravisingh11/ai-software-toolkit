# Review Finding Deduplication

- Prefer one canonical finding per root cause.
- Merge overlapping engineering, QA, and security findings when the same
  defect creates the same outcome.
- Keep the most actionable title and ID; append additional evidence from the
  other review lenses.
- Keep findings separate when symptoms look similar but the root causes differ.
- Do not create four comments that restate one issue only because four
  reviewers observed it.
